# Dataset card — dsh-research-bench v0.1.0

## Purpose

Measure whether a research plugin's *checking logic* detects the defects it claims to detect, on data the plugin's authors did not write and cannot tune against.

## Composition

| Dataset | Instances | Format | Labels |
|---|---:|---|---|
| citations | 100 | JSONL | `exists`, `mismatch_fields`, `update_notice`, `category` |
| stats | 0 (planned) | JSONL | `verdict` |

## Collection process

Everything is generated by `scripts/generate-citations.mjs` from a fixed table of ten fictional works. Provider responses (Crossref-shaped JSON, PubMed-shaped JSON, arXiv-shaped Atom) are constructed by the same script. No network calls, no scraping, no recorded real responses, no copyrighted content, no personal data.

## Ground truth

Labels are assigned by the generator per category (see `rubric/CITATIONS.md`). They do not depend on any plugin's output. A case's `providers` array is the complete evidence a plugin is allowed to use.

## Intended use

- Plugin authors measuring precision/recall before a release.
- Reviewers checking a README's accuracy claims.
- Regression detection when a plugin's matching logic changes.

## Out-of-scope use

- Claims about real papers, real authors or real journals.
- Training or tuning a detector (this is a test split).
- Any statement about provider API reliability or coverage.

## Biases and gaps

- Clean English metadata; no transliteration, name particles, mononyms, superscripts.
- Coarse error magnitudes; no near-duplicate titles across different works.
- Only three providers represented.
- Category frequencies are balanced by construction, not by real-world prevalence.

## Maintenance

Frozen datasets carry a `version` in `SUMMARY.json`; changing cases or labels requires a version bump and a CHANGELOG entry. The generator is the source of truth — cases are never edited by hand.
