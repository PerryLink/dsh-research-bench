# Dataset card — dsh-research-bench v0.1.0

## Purpose

Measure whether a research plugin's *checking logic* detects the defects it
claims to detect, on data the plugin's authors did not write and cannot tune
against.

## Composition

| Dataset | Instances | Format | Labels |
|---|---:|---|---|
| citations | 100 | JSONL | `exists`, `mismatch_fields`, `update_notice`, `category` |
| stats | 30 | JSONL | `verdict` (`consistent` / `inconsistent`), `issue` |
| claims | 50 | JSONL | `verdict` (`verified` / `insufficient` / `contradicted` / `disproven`), `category` |
| images | 100 pairs | PNG + JSONL | `manipulated` (bool), `kind` (`duplicate` / `horizontal-flip` / `vertical-flip` / null) |
| meta | 20 | JSONL | fixed/random effect, Q, I², τ², Egger flag |
| claims-heldout | 50 | JSONL | verdict + category; hash-pinned, same-author time split |

All three are frozen at v0.1.0; each carries a `version`, `total` and count map
in its `SUMMARY.json`. The repro, manuscripts and figures datasets are still
planned.

## Collection process

Everything is generated by deterministic, dependency-free scripts from fixed
tables: `scripts/generate-citations.mjs` (ten fictional works and their
Crossref/PubMed/arXiv-shaped responses), `scripts/generate-stats.mjs` (published
critical values), `scripts/generate-claims.mjs` (five synthetic paragraphs) and `scripts/generate-images.mjs` (deterministic PNG pairs) and `scripts/generate-meta.mjs` (closed-form meta-analysis cases).
No network calls, no scraping, no recorded real responses, no copyrighted
content, no personal data.

## Ground truth

- **citations**: labels are assigned by the generator per category (see
  `rubric/CITATIONS.md`); they do not depend on any plugin's output. A case's
  `providers` array is the complete evidence a plugin is allowed to use.
- **stats**: labels come from published critical-value tables, not from a
  plugin; the `.05`/`.01` critical value maps to `p = .05`/`.01`, and each
  inconsistent case changes exactly one element.
- **claims**: labels follow the category rules in `rubric/CLAIMS.md`. The v0.1
  cases were written from the same rubric as `dsh-claim-check`'s rules and one
  rule was corrected after a supported case failed. The resulting 1.0 scores are
  a **regression baseline, not an unbiased estimate** of real-manuscript
  accuracy; a held-out set authored without reference to the implementation is
  still planned.

The generators never read plugin output, and the committed data is checked
against regeneration in CI.

## Intended use

- Plugin authors measuring precision/recall before a release.
- Reviewers checking a README's accuracy claims.
- Regression detection when a plugin's matching logic changes.
- The claims v0.1 set is explicitly a regression baseline for `dsh-claim-check`.

## Out-of-scope use

- Claims about real papers, real authors or real journals.
- Training or tuning a detector (this is a test split; the claims caveat above
  explains why its v0.1 scores are not an unbiased held-out estimate).
- Treating the claims set as a held-out benchmark before the planned
  independently authored set exists.
- Any statement about provider API reliability or coverage.

## Biases and gaps

- Clean English metadata; no transliteration, name particles, mononyms,
  superscripts.
- Coarse error magnitudes; no near-duplicate titles across different works.
- Only three providers represented, and only for citations.
- Category frequencies follow the rubric, not real-world prevalence; several
  categories are deliberately small (for example 2 citation disagreements and
  5 quote-mined claims), so per-category rates are coarse.
- The claims cases are small and co-designed with the detector (see Ground
  truth).

## Maintenance

Frozen datasets carry a `version` in `SUMMARY.json`; changing cases or labels
requires a version bump and a CHANGELOG entry. The generators are the source of
truth — cases are never edited by hand, and CI regenerates all three datasets
and fails on drift.
